# Mercenaries Recompiled – Android port

**Status: all game sources are ported and the whole source set compiles under Android-style rules on a host
machine; it has not been built with the Android NDK or run on a device.** The environment this was written
in had no NDK, no network and no disc image, so no game frame has ever been rendered and performance is unknown.

## What "ported" means here
Every file the Windows build compiles now builds for Android, from the *same* sources (`#if XBOX_ANDROID`
branches keep the Windows build unchanged). `tests/check_android_sources.py` simulates the CMake build:
it reads the source lists out of `CMakeLists.txt`, compiles all 38 toolkit + 24 game sources with the same
include path and definitions (clang-strict: implicit function declarations are errors), and classifies every
unresolved symbol as libc / Android glue / recompiler output. It currently reports none unaccounted for.

| Area | Result |
|---|---|
| `main.c` (startup) | Builds as `mercenaries_android_main()`; token window handle, same D3D8 device parameters, Resolution option → back-buffer size, no-op x86 debug-register watchpoints, SIGSEGV-based crash report, 64 MB game-thread stack (the Windows build links with 64 MB) |
| `recomp_manual.c` (19,700 lines of game logic) | Compiles unmodified apart from fencing off two x86 host-register dumps |
| Controls / prompts | Gamepad binding logic kept; raw-mouse/`WM_*` code is Windows-only and inert (input = gamepad + touch overlay) |
| Dev overlay | Rewritten with a built-in pixel font (no GDI); set `MERCENARIES_FPS_OVERLAY=1` for FPS/frame-time graph |
| Dev menu | Win32 panel has no phone equivalent; same API kept (catalogs, request queues, developer.ini switches) |
| Plugins / mod saves / mod selector | Desktop-only (DLLs, separate selector app); behave exactly as "no mod selected" |
| PS2 upgrade assets, Lua scripts, catalogs, shader warm-up list | Generated by `gen_game_headers.py` (byte-exact vs the CMake scripts; Lua round-trip verified) |
| Win32 API surface | ~35 missing functions implemented in `compat/winapi_extra.c` incl. real INI files (`GetPrivateProfile*`), secure string functions, SHA-256 behind the BCrypt shim |

### Bugs found and fixed along the way (would have broken the Android build or game)
- `RtlInitUnicodeString` used 32-bit `wcslen` on 16-bit Xbox `WCHAR` strings (wrong length) – fixed in the toolkit.
- No case-insensitive file lookup: the game requests `D:\Media\Intro.XMV` while Android is case-sensitive. The importer
  now writes lower-case names and `kernel_path.c` folds requests the same way (tested end to end).
- Default thread stacks were 1 MB vs the Windows build's 64 MB reserve.
- Undeclared functions that MSVC tolerates and the NDK's clang rejects.
- `xbox_prepare_empty_cache_volume` had no POSIX implementation.

## Renderer: Direct3D 11 on OpenGL ES 3.0
`nv2a_pgraph_d3d11.c` + `d3d8_*.c` run **unmodified** on `cpp/d3d11_gles/` (a D3D11/DXGI/D3DCompile implementation
over GLES 3.0 with an HLSL→GLSL ES translator). Verified on Mesa GLES 3.2: all embedded shaders translate and
compile; the project's NV2A vertex-shader and register-combiner generators, fuzzed, produce 0 rejected shaders
(540 vertex / 1000 combiner); 28 pixel-level checks through the D3D11 API. Known gaps (GLES 3.0 limits): geometry
shaders (scaled lines fall back to thin lines), per-render-target blend state, wireframe, depth-clip control,
stencil-texture sampling, BC read-back, MSAA.

## Verified by `tests/run-host-tests.sh` (Linux; GPU tests use Mesa llvmpipe)
XDVDFS importer · AArch64 MMIO decoder · `mmap` guest-memory layout · Win32 compat (INI, strings, paths, atomics) ·
SHA-256 (NIST vectors) · case folding · whole-source-set check · HLSL translator · D3D11-on-GLES · shader generators.

## Not done / not verifiable here
1. **Game code.** Generated from *your* disc by `tools/recomp` on a PC (default location `ports/mercenaries/src/recomp/gen`,
   or `-PmercGenDir=`). Without it the app builds as an importer + status shell.
2. **First NDK build.** CMake is untested against a real NDK. Expect to iterate on compile/link errors
   (the host check covers undeclared functions, missing files and unresolved symbols, not NDK-header differences).
3. **Run-time behaviour on a phone**: speed (lifted x86 + NV2A emulation), shader-compile hitching, thermal limits.
4. **DSP56300 audio**: the prebuilt library is MSVC-only; rebuild `third_party/dsp56300` for `aarch64-linux-android` or audio runs without it.
5. **Mods, plugins, dev menu panel, keyboard/mouse** are not available on Android.

## Building
Run `tools/recomp` on a PC with your disc image, open this folder in Android Studio (NDK 26.3), then
`./gradlew assembleDebug`. arm64-v8a only. Needs Python 3 on the build machine (header generation).
Install, tap *Import*, choose your `.iso`, tap *Play*. Logs: `adb logcat -s MercRecomp MercGame d3d11gles`.
